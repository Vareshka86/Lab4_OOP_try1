## Что значит «с учётом состояния»

Копирование «по умолчанию» (то, что делает компилятор, если ничего не написать) переписало бы все поля
подряд, и у устройства возникли бы три ошибки:

| Что скопировал бы компилятор | Чем это плохо |
|------------------------------|---------------|
| поля устройства, но не счётчик `existingCount_` | копия не попала бы в счётчик существующих устройств, а её деструктор его уменьшил бы — счётчик ушёл бы в минус |
| накопленную энергию и час начала учёта | одна и та же энергия числилась бы у оригинала и у копии; сумма по устройствам больше общего счётчика |
| имя | два устройства с одним именем |

Поэтому копирование написано вручную. Правила, которые выбраны и проверены тестами:

| Что | Конструктор копирования | Присваивание `a = b` |
|-----|-------------------------|----------------------|
| Параметры (мощность, яркость, цвет, температура, режим, нагрузка, напряжение) | копируются | копируются |
| Состояние «включено/выключено» | копируется | копируется |
| Имя | `имя + « (копия)»` | остаётся своим |
| Накопленная энергия устройства | у копии 0 кВт·ч | остаётся своей |
| Счётчик устройств | увеличивается | не меняется |
| Учёт энергии | если копия включена, учёт начинается с текущего часа | прошлое засчитывается по **старым** параметрам, затем новый интервал с текущего часа |

Копия — новое устройство, поэтому начинает со своих 0 кВт·ч. Присваивание не создаёт и не уничтожает
устройство: оно остаётся тем же (своё имя и история), но получает чужие параметры.

## Иерархия (v1.0)

![Диаграмма классов, версия v1.0](uml/SmartHome.png)

Копирование есть в каждом классе иерархии, но с разной видимостью:

| Класс | Конструктор копирования и присваивание | Что копирует сам |
|-------|----------------------------------------|------------------|
| SmartDevice | защищённые (`protected`) | состояние; увеличивает счётчик; имя с пометкой |
| PoweredDevice | защищённые | мощность; не копирует энергию |
| ISensor | защищённые, `= default` | ничего: полей нет |
| LightBulb, Thermostat, SmartOutlet | **открытые** | свои параметры + вызов копирования базовых частей |

Зачем `protected` в абстрактных классах: объекты SmartDevice и PoweredDevice не существуют сами по
себе, а присваивание через ссылку на базовый класс скопировало бы только часть объекта (**срезка**):
`SmartDevice& a = lamp; SmartDevice& b = thermostat; a = b;` — лампа получила бы «чужое» состояние, а
параметры остались бы прежними. С `protected` так написать нельзя: копировать можно только конкретные
объекты одного класса.

## Конструктор копирования в иерархии

```cpp
// LightBulb
LightBulb::LightBulb(const LightBulb& other)
    : PoweredDevice(other), brightness_(other.brightness_), color_(other.color_) {}

// PoweredDevice
PoweredDevice::PoweredDevice(const PoweredDevice& other)
    : SmartDevice(other), powerConsumption_(other.powerConsumption_),
      energyKWh_(0.0), meterStartHours_(clockHours_) {}

// SmartDevice
SmartDevice::SmartDevice(const SmartDevice& other)
    : name_(other.name_ + " (копия)"), isOn_(other.isOn_) { ++existingCount_; }
```

Каждый уровень копирует **свои** поля и в списке инициализации вызывает копирование базового класса
(`PoweredDevice(other)` — лампа передаётся как её часть PoweredDevice). Если базовую часть не
упомянуть, компилятор построит её конструктором по умолчанию — и компиляция остановится, потому что у
SmartDevice такого конструктора нет.

**Множественное наследование.** У розетки две базовые части, поэтому в списке инициализации
вызываются обе:

```cpp
SmartOutlet::SmartOutlet(const SmartOutlet& other)
    : PoweredDevice(other), ISensor(other), load_(other.load_), voltage_(other.voltage_) {}
```

## Присваивание и порядок действий

```cpp
LightBulb& LightBulb::operator=(const LightBulb& other)
{
    if (this != &other)                       // самоприсваивание: a = a ничего не делает
    {
        PoweredDevice::operator=(other);      // 1) прошлое засчитывается по СТАРЫМ параметрам
        brightness_ = other.brightness_;      // 2) только потом свои поля меняются
        color_ = other.color_;
    }
    return *this;                             // возвращает ссылку: работает a = b = c
}
```

Порядок важен. В `PoweredDevice::operator=` первым вызывается `updateMeter()`, а он берёт мощность
через виртуальную `getPowerUsage()` — у лампы она зависит от яркости. Яркость пока старая, потому что
лампа меняет свои поля **после** вызова базового присваивания. Если бы порядок был обратным, прошлые
часы работы посчитались бы по новой яркости. Пример теста: лампа 100 Вт работала 2 часа и получила
параметры лампы 40 Вт × 25 %; ей засчитано ровно 0,200 кВт·ч (100 Вт × 2 ч), а не 0,020.

Четыре сочетания состояний, которые проверены отдельно: «включена ← выключена» (приёмник выключается,
прошлое засчитано), «выключена ← включена» (приёмник включается, учёт с этого момента), «включена ←
включена» (мощность сменилась на ходу), «выключена ← выключена».

## Проверка самоприсваивания

Проверка `this != &other` защищает от `a = a`. Без неё `PoweredDevice::operator=` всё равно ничего бы не
испортил, но для классов с динамической памятью (`delete` старого перед копированием) самоприсваивание
без проверки разрушило бы данные. В программе правило применяется единообразно ко всем классам.

## Динамические ресурсы

В классах устройств нет `new`/`delete`: все поля — числа и `std::string`, который копируется сам и
глубоко. Поэтому «глубокое копирование» здесь — это копирование строки `color_` и имени; разделяемых
указателей между копиями нет, и изменение копии не затрагивает оригинал (тест 8).

## Защита от ошибок

Копирование не может нарушить инварианты: параметры берутся из объекта, уже прошедшего проверку.
Для розетки нагрузка не больше номинальной мощности сохраняется, потому что копируются обе
величины вместе (проверено). Исключений копирование не бросает.

**Проверка.** Тесты программы — 74 проверки из 74 (в версии v0.3 было 52). Отдельная тестовая программа
части 4 — 31 проверка из 31: типы (конкретные классы копируются, абстрактные базы и интерфейс снаружи — нет);
счётчик устройств при копировании, присваивании и уничтожении копии; пометка в имени; энергия копии
и общий счётчик; четыре сочетания состояний при присваивании; самоприсваивание и цепочка
`(a = b) = c`; термостат и розетка; удаление включённой копии через `SmartDevice*`. Тестовые программы
частей 1–3 (16 из 16, 20 из 20, 22 из 22) проходят: в них заменены только проверки «копирование
запрещено» на «копирование разрешено».
