## Интерфейс ISensor

```cpp
class ISensor {
public:
    virtual ~ISensor() = default;                 // виртуальный деструктор
    virtual double getCurrentVoltage() const = 0; // чисто виртуальная функция
};
```

**Интерфейс** — абстрактный класс без полей, только с чисто виртуальными функциями. Он задаёт «что
умеет любой датчик», а реализацию дают классы, которые его наследуют. Отдельного слова `interface` в
C++ нет; приставка `I` в имени — договорённость, чтобы интерфейс было видно сразу.

Деструктор виртуальный, потому что объект могут удалить через указатель на ISensor (тест 7). `= default`
значит «тело пустое, пусть его создаст компилятор».

## Класс SmartOutlet

```cpp
class SmartOutlet : public PoweredDevice, public ISensor { ... };
```

| Член класса | Что делает |
|-------------|------------|
| `SmartOutlet(name, maxPower, load, voltage)` | выключенная розетка; `maxPower` — наибольшая нагрузка (номинальная мощность PoweredDevice), `load` — мощность прибора от 0 до `maxPower`, `voltage` — напряжение сети 180–260 В |
| `getPowerUsage()` | **переопределена**: включённая розетка тратит мощность подключённого прибора |
| `getCurrentVoltage()` | **реализует ISensor**: напряжение сети; датчик стоит на входе, поэтому работает и у выключенной розетки |
| `getCurrentAmperage()` | ток: мощность сейчас / напряжение (P = U × I) |
| `setLoad(load)` | подключить прибор другой мощности; сначала `updateMeter()` — энергия до изменения по старой нагрузке |
| `setVoltage(voltage)` | изменить напряжение сети (имитация показаний датчика); на мощность не влияет |
| `~SmartOutlet()` | выключает включённую розетку, чтобы энергия попала в учёт |

Конструктор вызывает в списке инициализации только `PoweredDevice(name, maxPower)`: у ISensor нет
конструктора с параметрами, его конструктор по умолчанию вызывается сам. Базовые части строятся в
порядке, в котором они перечислены в объявлении класса: сначала PoweredDevice (а в нём — SmartDevice),
потом ISensor; разрушаются в обратном порядке.

## Один объект — три «роли»

```cpp
SmartOutlet kettle("Чайник", 3500.0, 2000.0, 230.0);
SmartDevice* device = &kettle;   // как умное устройство: turnOn(), getStatus()
PoweredDevice& powered = kettle; // как устройство с питанием: getPowerUsage() = 2000 Вт
ISensor& sensor = kettle;        // как датчик: getCurrentVoltage() = 230 В
```

Розетку можно передать в любое место, где ждут SmartDevice, PoweredDevice или ISensor. Через каждый
из этих указателей и ссылок вызываются версии функций SmartOutlet.

Через ссылку на ISensor видна только функция датчика: `sensor.turnOn()` не скомпилируется — у ISensor
такой функции нет. И наоборот, через `SmartDevice*` нельзя вызвать `getCurrentVoltage()`.

## Поиск датчиков через dynamic_cast

```cpp
for (const SmartDevice* item : devices) {
    const ISensor* itemSensor = dynamic_cast<const ISensor*>(item); // nullptr, если объект не датчик
    if (itemSensor != nullptr) { ... itemSensor->getCurrentVoltage() ... }
}
```

В массиве `SmartDevice*` лежат лампа, розетка и термостат. `dynamic_cast` во время работы программы
проверяет настоящий тип объекта: для розетки он возвращает указатель на её часть ISensor, для лампы и
термостата — `nullptr`. Это «перекрёстное» приведение — из одной ветви наследования (SmartDevice) в
другую (ISensor); оно работает, потому что у классов есть виртуальные функции.

## Почему нет «ромба»

«Ромб» возникает, когда два базовых класса сами наследуют один общий класс: тогда в объекте
оказываются две копии общей части, и нужно виртуальное наследование (`virtual public`). Здесь
ISensor не наследует SmartDevice, поэтому часть SmartDevice в розетке одна — имя, состояние и счётчик
устройств не дублируются, и виртуальное наследование не нужно.

## Защита от ошибок

| Ошибка | Реакция |
|--------|---------|
| нагрузка меньше 0 или больше номинальной мощности, не число | `std::invalid_argument`; в конструкторе объект не создаётся, в `setLoad()` нагрузка прежняя |
| напряжение вне 180–260 В, не число | `std::invalid_argument`; в `setVoltage()` напряжение прежнее |
| пустое имя, мощность 0 и меньше | проверяют конструкторы SmartDevice и PoweredDevice |

Ток считается делением на напряжение; оно всегда не меньше 180 В, поэтому деления на ноль нет.

**Проверка.** Тесты программы — 52 проверки из 52 (в версии v0.2 был 41). Отдельная тестовая
программа части 3 — 22 проверки из 22: ISensor абстрактный, без полей, с виртуальным деструктором и не
связан с SmartDevice; SmartOutlet — наследник обоих классов, не абстрактный и не копируется; указатель
на ISensor указывает на другую часть объекта, чем `SmartDevice*`, а `dynamic_cast` находит тот же
объект; граничные значения нагрузки и напряжения; учёт энергии при смене нагрузки и напряжения;
`delete` включённой розетки через `SmartDevice*`, `PoweredDevice*` и `ISensor*` засчитывает её энергию
и возвращает счётчик устройств. Тестовые программы частей 1 и 2 (16 из 16, 20 из 20) проходят без изменений.
