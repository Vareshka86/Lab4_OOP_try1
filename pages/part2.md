## Класс Thermostat

| Член класса | Что делает |
|-------------|------------|
| `Thermostat(name, power, temperature, mode)` | создаёт выключенный термостат; неверные параметры — `std::invalid_argument` |
| `~Thermostat()` | выключает включённый термостат, чтобы энергия последнего интервала попала в учёт |
| `getStatus()` | строка состояния: «Термостат «Спальня»: включён, режим «обогрев», температура 22 °C, …» |
| `getTemperature()`, `setTemperature(t)` | заданная температура; вне 5–35 °C — исключение, термостат не меняется |
| `getMode()`, `setMode(mode)` | режим работы |
| `static modeName(mode)` | название режима по-русски: «обогрев», «охлаждение», «эко» |

Режим — перечисление внутри класса:

```cpp
class Thermostat : public PoweredDevice {
public:
    enum class Mode { Heating, Cooling, Eco };
    ...
};

Thermostat bedroom("Спальня", 1500.0, 22, Thermostat::Mode::Heating);
```

`enum class` — строгое перечисление: значения пишутся с именем перечисления (`Thermostat::Mode::Eco`) и
сами в числа не превращаются, поэтому перепутать режим с температурой нельзя.

## Реализация по умолчанию и переопределение

```cpp
// PoweredDevice - реализация по умолчанию
virtual double getPowerUsage() const;           // включено -> вся номинальная мощность

// LightBulb - переопределяет
double getPowerUsage() const override;          // номинальная мощность × яркость / 100

// Thermostat - не переопределяет: работает версия PoweredDevice
```

Так в одной иерархии видны оба случая. Для лампы на 60 Вт с яркостью 50 % вызов через ссылку на
PoweredDevice даёт 30 Вт, для включённого термостата на 1500 Вт — все 1500 Вт (тест 2).

Температура и режим на мощность не влияют, поэтому `setTemperature()` и `setMode()`, в отличие от
`setBrightness()` у лампы, не вызывают `updateMeter()`.

## Массив устройств через указатели на базовый класс

```cpp
SmartDevice* devices[4] = {
    new LightBulb("Кухня", 60.0, 100, "тёплый белый"),
    new Thermostat("Спальня", 1500.0, 22, Thermostat::Mode::Heating),
    new LightBulb("Коридор", 40.0, 50, "белый"),
    new Thermostat("Кабинет", 1000.0, 24, Thermostat::Mode::Cooling)};

for (SmartDevice* device : devices) device->turnOn();
PoweredDevice::advanceClock(2.0);
for (SmartDevice* device : devices) device->turnOff();
for (const SmartDevice* device : devices) std::cout << device->getStatus() << '\n';

for (SmartDevice*& device : devices) { delete device; device = nullptr; }
```

- В массиве лежат указатели одного типа — на абстрактный SmartDevice, а объекты за ними разных
  классов. Один и тот же вызов `device->getStatus()` печатает строку лампы или термостата — версия
  выбирается по настоящему типу объекта (полиморфизм).
- Создать массив самих объектов SmartDevice нельзя: класс абстрактный. Поэтому — указатели, а
  объекты создаются через `new`.
- `delete device` через указатель на SmartDevice работает правильно, потому что деструктор
  SmartDevice виртуальный: вызываются деструкторы всех уровней, начиная с LightBulb или Thermostat.
- В последнем цикле `SmartDevice*&` — ссылка на элемент массива, поэтому `device = nullptr` обнуляет
  сам элемент, а не копию указателя.

**Статистика.** После двух часов работы: Кухня 60 Вт, Спальня 1500 Вт, Коридор 40 Вт × 50 % = 20 Вт,
Кабинет 1000 Вт; (60 + 1500 + 20 + 1000) Вт × 2 ч / 1000 = 5,160 кВт·ч. Тест сверяет с этим числом прирост
общего статического счётчика `PoweredDevice::getTotalEnergyConsumed()` и проверяет, что после удаления
счётчик устройств `SmartDevice::getExistingCount()` вернулся к прежнему значению.

## Защита от ошибок

| Ошибка | Реакция |
|--------|---------|
| температура вне 5–35 °C в конструкторе | `std::invalid_argument`, объект не создаётся, счётчик устройств прежний |
| `setTemperature()` вне 5–35 °C | `std::invalid_argument`, температура прежняя |
| пустое имя, мощность 0 и меньше | как у лампы: проверяют конструкторы SmartDevice и PoweredDevice |

**Проверка.** Тесты программы — 41 проверка из 41 (в версии v0.1 было 27). Отдельная тестовая программа
части 2 — 20 проверок из 20: Thermostat не абстрактный и не копируется; температуры 5 и 35 °C
принимаются, 4 и 36 — нет; исключение в конструкторе не меняет счётчик устройств; мощность термостата
равна реализации по умолчанию; смена режима и температуры у включённого термостата не нарушает учёт;
`delete` включённых устройств через `SmartDevice*` и `PoweredDevice*` засчитывает их энергию.
Тестовая программа части 1 (16 из 16) проходит без изменений.
